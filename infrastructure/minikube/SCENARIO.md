# Cloud Secrets Manager — Minikube Interview Scenario

A full local deployment of the stack on minikube: 3 Spring Boot services, Postgres, frontend, plus Prometheus + Grafana + Alertmanager + Loki + Tempo. Built to be demoable in ~15 minutes.

## Prerequisites (one-time)

```bash
brew install minikube kubectl helm openssl
# Docker Desktop (or colima) must be running
```

## Bring it up

From `infrastructure/minikube/scripts/`:

```bash
./00-start-minikube.sh          # minikube start + ingress/metrics addons
./01-build-images.sh            # docker build + minikube image load (x4)
./02-bootstrap-secrets.sh       # generates JWT / AES-256 key / DB creds
./03-deploy-app.sh              # postgres StatefulSet + helm install
./04-deploy-monitoring.sh       # kube-prometheus-stack + loki + tempo
./05-smoke-test.sh              # end-to-end health check
```

Then add to `/etc/hosts` (the scripts print the exact line):

```
<minikube-ip> csm.local grafana.local prometheus.local alertmanager.local
```

## The demo — click-through order

Each step has (1) command/URL, (2) what to show on screen, (3) the point you are making.

### 1. "The cluster" — `kubectl get pods -A`

```bash
kubectl get pods -A
```

**Show:** three namespaces — `csm`, `monitoring`, `tracing`. No cloud-sql-proxy sidecars. No ExternalSecrets stuck in `SecretSyncError`.

**Point:** The chart is production-shaped (Cloud SQL proxy, Workload Identity, ESO against GCP Secret Manager) but I gated those behind feature flags. Same chart, two paths.

### 2. "The app works" — open `http://csm.local`

Log in as `smoketest-*@example.com` / `SmokeTest!234` (created by `05-smoke-test.sh`), or sign up a new user. Create a project. Create a secret.

**Point:** The backend encrypts the value with AES-256-GCM before it ever touches Postgres. The DB column is `TEXT`, not `BYTEA` — we store base64 of IV ‖ ciphertext ‖ auth-tag. JWT is HMAC-SHA256 with a key that was generated by `02-bootstrap-secrets.sh` and injected via a Kubernetes Secret.

### 3. "Metrics" — Grafana CSM dashboard

```bash
kubectl port-forward -n monitoring svc/prometheus-grafana 3000:80
# open http://localhost:3000 — admin / admin
```

Navigate to the provisioned CSM dashboard. Point at RED metrics (Rate, Errors, Duration) for each service. Generate traffic from the frontend and watch the line move.

**Point:** Spring Boot `/actuator/prometheus` scraped every 15 s by a `ServiceMonitor` CRD. The CRD is the Kubernetes-native way to tell Prometheus "scrape any Service that matches this label". Compare to classic `prometheus.yml` static config.

### 4. "Targets are green" — Prometheus

```bash
kubectl port-forward -n monitoring svc/prometheus-kube-prometheus-prometheus 9090:9090
# http://localhost:9090/targets
```

**Show:** `secret-service`, `audit-service`, `notification-service` all `UP`. Query:

```
rate(http_server_requests_seconds_count{job="secret-service"}[1m])
```

**Point:** Pull model. Prometheus scrapes targets; the app is passive.

### 5. "Traces" — Grafana → Explore → Tempo

In Grafana, Explore → datasource **Tempo** → Search recent traces. Pick a `POST /api/projects/.../secrets` trace.

**Show:** span goes `secret-service` → Postgres JDBC → `audit-service` (via WebClient). Latency per span is visible.

**Point:** OTLP/HTTP to Tempo at `http://tempo.tracing.svc:4318`. Sampling 100% in dev (`application-observability.yml`), would drop to 1–10% in prod.

### 6. "Logs correlate" — Grafana → Explore → Loki

```
{namespace="csm", app_kubernetes_io_name="secret-service"} |= "traceId"
```

Copy a `traceId` from a log line, paste it in the Tempo datasource: the trace shows up.

**Point:** Logback pattern `[%X{traceId:-},%X{spanId:-}]` (see `application-observability.yml`) — MDC carries the trace context into every log line. Log-to-trace correlation is the cheapest observability win you can add.

### 7. "The kill shot" — an alert fires, then resolves

```bash
kubectl delete pod -n csm -l app.kubernetes.io/name=secret-service
```

Port-forward Alertmanager:

```bash
kubectl port-forward -n monitoring svc/prometheus-kube-prometheus-alertmanager 9093:9093
# http://localhost:9093
```

Within ~1 minute, `KubePodNotReady` (shipped with kube-prometheus-stack) fires. Once the replacement pod readiness probes pass, it auto-resolves.

**Point:** Alerts live in a `PrometheusRule` CRD (same pattern as ServiceMonitor). PrometheusRule → Prometheus evaluates → fires to Alertmanager → routes to the right receiver (Slack, PagerDuty, etc). In our `infrastructure/monitoring/alerts/prometheus-rules.yaml` we have 17 custom CSM alerts for SLO breaches, DB connection exhaustion, secret rotation failures, etc.

## What would change in prod (GCP)

| Local (this demo) | Production (GCP/GKE) |
|---|---|
| In-cluster Postgres StatefulSet, PVC on minikube driver | Cloud SQL PostgreSQL HA, Cloud SQL Auth Proxy sidecar, IAM auth |
| `kubectl create secret` with random bytes | GCP Secret Manager + External Secrets Operator → auto-synced Secrets |
| Pod ServiceAccounts with no annotations | Workload Identity: KSA ↔ GCP SA binding, no long-lived keys |
| `minikube addons enable ingress` (nginx) | ingress-nginx on GKE + cert-manager + Let's Encrypt |
| Pub/Sub env vars set to `""`, EMAIL_ENABLED=false | Real Pub/Sub topic + SendGrid API key |

See `infrastructure/terraform/` for the GCP IaC and `infrastructure/cloudrun/` for the alternative serverless target.

## Architecture

```
ns: csm                          ns: monitoring              ns: tracing
  frontend                         prometheus                   tempo
  secret-service   ──┐             grafana
  audit-service    ──┼──> postgres loki + promtail
  notification-svc ──┘             alertmanager
  ingress (nginx)
```

- `/api` routes to `secret-service` (Spring Boot)
- `/api/audit` routes to `audit-service`
- `/api/notifications` routes to `notification-service`
- `/` routes to the Vite React frontend

## Troubleshooting cheat sheet

| Symptom | Fix |
|---|---|
| Pods `ImagePullBackOff` | `./01-build-images.sh` again — `pullPolicy: Never` requires the image loaded into minikube's docker daemon |
| `ENCRYPTION_KEY must be exactly 32 bytes` | `rm infrastructure/minikube/.secrets.env && ./02-bootstrap-secrets.sh` |
| Secrets UI shows "Network error" | `/etc/hosts` missing entry — see `minikube ip` output |
| Prometheus targets `DOWN` | ServiceMonitor didn't match Service labels — check `kubectl -n monitoring get servicemonitor` uses `app.kubernetes.io/name` (the legacy `infrastructure/monitoring/servicemonitors/` uses `app:` which does **not** match our chart labels — intentionally replaced by `infrastructure/minikube/monitoring/servicemonitors.yaml`) |
| Grafana shows "No data" | Give Prometheus 30 s after deploy; first scrape cycle takes `30s` |
| Smoke test fails on login | DB init may have raced Spring's first connection. `kubectl -n csm rollout restart deploy/secret-service` |
